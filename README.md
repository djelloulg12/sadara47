# منصة النادي الرياضي الصدارة

منصة عربية RTL لفوج السباحة: صفحة عامة، ولوحة إدارة كاملة، ولوحات مخصصة للمدربين والرياضيين وأولياء الأمور، مبنية على Firebase (Auth + Firestore + Storage) مع خادم Python/SQLite مكافئ للتشغيل المحلي.

## البنية

| الملف | الدور |
| --- | --- |
| `index.html` | صفحة واحدة تحمّل Firebase compat SDK و`qrcodejs` وملفات التطبيق |
| `app.js` | الواجهة كاملة: الصفحة العامة، لوحة الإدارة، لوحات الأدوار، محرك الطباعة |
| `firebase-adapter.js` | جسر يحوّل طلبات `/api/*` إلى Firebase Auth + Firestore + Storage |
| `firebase-config.js` | إعدادات مشروع `sadara-platform` |
| `firestore.rules` / `storage.rules` | صلاحيات الوصول للبيانات وملفات المدربين |
| `firebase-public/` | **نسخة النشر الفعلية** على Firebase Hosting |
| `server.py` + `schema.sql` | خادم API مكافئ بـ SQLite للتشغيل المحلي والاختبار |
| `sadara-local.db` | قاعدة التطوير المحلية (not tracked by Git) |

> **مهم:** المجلد `firebase-public/` هو ما يُنشر. أي تعديل على `app.js` أو `styles.css` أو `index.html` أو `firebase-adapter.js` يجب تكراره في `firebase-public/`.There is a GitHub Actions step تتحقق من ذلك وتمنع النشر عند اختلاف النسختين.

## التشغيل المحلي

```bash
python server.py
```

أو `npm run serve`. الخادم ينشئ `sadara-local.db` تلقائيًا، ويضيف الأعمدة الجديدة
للقواعد القديمة دون فقدان البيانات. وللقاعدة مسار آخر عبر `SADARA_DB_PATH`.

### تسجيل الدخول محليًا

إن كانت `sadara-local.db` جديدة، ينشئ الخادم ثلاثة حسابات تطوير حتى لا تبقى صفحة
الدخول بلا من يستطيع تجاوزها:

| البريد | الدور | كلمة المرور |
| --- | --- | --- |
| `admin@sadara.local` | مدير | `Sadara@2026` |
| `president@sadara.local` | رئيس النادي | `Sadara@2026` |
| `coach@sadara.local` | مدرب | `Sadara@2026` |

> كلمة مرور **للتطوير المحلي فقط**، ومعروفة للجميع. لا تستعملها على المنصة
> المنشورة، وغيّرها قبل أي استعمال حقيقي: `npm run user`

ولإنشاء حساب أو تغيير كلمة مرور — تُسأل كلمة المرور دون أن تظهر ولا تدخل سجلّ
الأوامر:

```bash
npm run user
```

### حسابات الإنتاج

على المنصة المنشورة تُنشأ من `tools/seed-accounts.py` بعد تفعيل Firebase
Authentication، وكلمة المرور تأتي منك ولا تُخزَّن في المستودع.

## الصلاحيات

| الدور | ما يستطيع فعله |
| --- | --- |
| `admin` / `president` | كل شيء: الطلبات، الأسعار، السباحون، البرنامج، الحضور، الإعلانات، الوثائق |
| `coach` | تسجيل الحضور، قراءة البرنامج، قراءة ملفه هو، لوحة المدرب |
| `swimmer_adult` / `swimmer_minor` / `parent` / `member` | لوحات خاصة: الحضور، البطاقة، البرنامج، الإعلانات |

في Firestore، كل حساب إداري يحتاج مستندًا في `users/{uid}` يحمل `role`، لأن القواعد تعتمد على هذا الحقل. لربط حساب لاعب ببطاقة انخراط، ضع `member_no` في نفس المستند (أو `phone`).

## الطباعة

كل صفحة فيها زر 🖨 يطبع **ورقة مخصّصة** لتلك الصفحة فقط، بترويسة النادي وتاريخ الطباعة وتذييل بيانات التواصل:

- بطاقات الانخراط (2 × 8.5×5.5 سم في الصفحة A4، بطاقة واحدة عند الطلب)
- استمارة الانخراط — قائمة السباحين السارية
- كشف حضور اليوم (بعمود توقيع)
- قائمة فوج واحد أو جدول كل الأفواج A4
- قوائم الطلبات والسباحين والاشتراكات والإعلانات والبرنامج والإعدادات
- استمارة التسجيل الرسمية A4 (نافذة منفصلة قابلة للملء)
— Coach: لوحات المدرب والرياضي: بطاقتي، سجل حضوري، برنامجي

`Ctrl+P` مباشرةً تطبع الصفحة الحالية بشكل نظيف أيضًا.

## البيانات

- السباحون، الطلبات، الاشتراكات، الحضور، الإعلانات، البرنامج الأسبوعي، البطاقات، وثائق المدربين.
- المبالغ تُحتسب آليًا: قيمة الاشتراك + النقل + البدلة، والأسعار قابلة للتعديل من صفحة «إدارة الاشتراكات».
- سجل الحضور يُخزَّن بمستند واحد لكل سباح في اليوم (`att_YYYY-MM-DD_<member>`)، فالتسجيل المتكرر يحدّث نفس السجل.

## النشر

ينشر GitHub Actions إلى Firebase Hosting وينشر قواعد Firestore/Storage، عند الدفع إلى `main` أو `master`، أو يدويًا من تبويب Actions.

المتطلب: السر `FIREBASE_SERVICE_ACCOUNT` في إعدادات المستودع.

للنشر على Render/Docker: `Dockerfile` + `render.yaml` جاهزان، ويستخدم الخادم متغير `PORT`.

انظر `DEPLOY.md` لقائمة المتغيرات وقواعد الأمان.
